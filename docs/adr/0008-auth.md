# ADR 0008 — Real authentication (replaces demo sessions)

- **Status:** Accepted · supersedes ADR 0005
- **Date:** 2026-08-01
- **Context:** The MVP shipped with a local demo session (ADR 0005). The product
  is now required to be production-ready: no demo users, no implicit sessions,
  real accounts with proper security.
- **Decision:**
  - `User.passwordHash` (bcrypt, cost 12) — registration, login, password
    change; password policy enforced (≥8, letter+number, ≤128).
  - Server-side `Session` table: opaque 32-byte token in an httpOnly SameSite
    cookie; only the SHA-256 hash is stored; sessions are revocable
    (logout / password change), expire after 30 days, slide on activity.
  - Login is timing-equalized and returns a generic error (no account
    enumeration). Auth endpoints are rate limited (10/15 min/IP).
  - All auth reads/writes isolated in `src/lib/auth/` — the swap-in seam is now
    the real thing, and swapping providers (NextAuth/Clerk) still touches one
    module.
- **Consequences:** Demo user and auto-sign-in are gone; accounts are created
  via registration (the seed script that previously bootstrapped an account
  was removed in a later repo cleanup). Email verification and password reset
  remain Phase 2+ (`emailVerifiedAt` reserved).
